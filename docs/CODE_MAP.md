# Code Map

What each source file does, grouped by layer. `transport=cli` (default): every model call shells out to a CLI provider via `agent.py`. `transport=api` (claude+gemini): model calls go to the provider SDKs directly via `app/services/api_transport.py`.

> Pipeline at a glance: **upload PDF → extract TOC → pick a section → generate**. A job runs `per-section extract → DAG-parallel content phases`; each phase emits **markdown** stored on its own `phase_outputs` row. There is no source-map step and no assembly step — the per-phase markdown is the deliverable. See `CLAUDE.md` for the architecture narrative.

---

## Entry point
- **`main.py`** — FastAPI app factory + `lifespan` (mounts API + SPA, starts the embedded worker when `worker_concurrency > 0`; on boot sweeps stuck books/phases to `failed` and calls `jobs.reclaim_orphans_on_startup`: reset-all when no live peer is in the `workers` registry, else uses the lease window — C5 peer-aware reclaim).

## `app/` root
- **`config.py`** — `Settings` (env/`.env`): DB URL, auth tokens, queue/worker knobs, resilience (heartbeat / reclaim / per-attempt timeout / `failover_provider_order`), extract gates, Notion config, per-provider usage caps. Judge/extract provider·model selection was **removed from settings** (migration 0037) and now lives in the DB `launch_defaults` singleton, edited at `/settings`. `gemini_api_key`/`gemini_model` are **vestigial** (unread; leftover from the removed SDK).
- **`db.py`** — async SQLAlchemy engine + `SessionLocal`.
- **`auth.py`** — Bearer-token / `?token=` dependency. Empty `AUTH_TOKEN` ⇒ everyone is `anonymous`.
- **`log.py`** — loguru setup (stderr + `var/server.log`). Format carries the **date** (`YYYY-MM-DD HH:mm:ss.SSS`) and the file sink rotates **daily** at midnight (retention 7 days), so consecutive runs don't conflate across a midnight boundary.

## `app/api/v1/` — HTTP surface
- **`books.py`** — upload book, **`/from-notion`** (pull a textbook from the Notion lessons tree), list/get/delete, TOC extraction SSE stream, **`POST /{id}/toc/retry`** (re-run prep for a `failed`, `toc_extracting`, OR `toc_review` book; worklog 0073/0108), **`POST /{id}/toc/accept`** (operator accept: 409 unless `toc_review` → flips to `toc_ready`, preserves `toc_validation`/`toc_validation_detail` as audit trail; worklog 0108), delete a TOC entry (PR37: **refuses with 409 while a job for it is in flight**, then cascade-removes the section's jobs). (`_start_toc_extraction` is the shared fire-and-forget trigger used by upload/from-notion/retry.) `stream_toc` has a `toc_review` SSE branch that emits the `toc_validation_detail` for the review panel. `BookOut` exposes `toc_validation`/`toc_validation_detail` + `source_language`.
- **`jobs.py`** — the core surface: `POST …/sections/{toc}/generate` (PR37: body accepts `custom_prompts` `{phase: markdown}` + `selected_phases` subset, validated server-side — unknown/`extract` phase or >20k-char prompt → 400; a custom/subset launch is always fresh, never reuses a plain job; response carries `planned_phases`/`added_phases`), `GET /jobs/{id}`, `POST /jobs/{id}/retry`, `POST /jobs/{id}/retry-archive` (re-run the best-effort Notion archive for a `done`+un-archived job; worklog 0086; **`?force=true` (0114)** overrides the already-archived 409 and clears+rewrites stale leaf pages via `archive_job(force=True)` — regen refresh; **backgrounded (0116)**: immediate `{job_id, queued, already_running}` receipt + `_FORCE_REARCHIVE_TASKS` in-flight guard, double-POST no-ops — inline it was cancelled mid-clear by client disconnects; non-force stays inline/JobOut), `POST /jobs/{id}/cancel`, `GET /jobs/{id}/stream` (SSE progress), `GET /jobs/{id}/download` (ZIP of per-phase markdown), `GET /agent/models` (manifest + a live-fleet `fleet` capability block from `workers_repo.aggregate_fleet_capability` — union of installed CLIs + api creds over online workers; DB-touching, 5s-polled by the launcher), `GET /agent/stats` (usage windows + per-model breakdown + sparkline series).
- **`batch.py`** — fleet batch surface: `POST /jobs/batch` (fan out one job per lesson; PR37: same `custom_prompts`/`selected_phases` body; `output_language` field — `null` defaults to the book's `source_language` (via `resolve_output_language_for_book(explicit, book.source_language, global_default)`), explicit pick still wins; **resume-aware** — a failed/cancelled section is resumed not recreated; `preview` mode returns disposition with zero writes; `relaunch_mode` resume|discard), `POST /jobs/batch/{id}/cancel` (cancel-all), `POST /jobs/batch/{id}/resume` (resume failed/cancelled), `POST /jobs/batch/{id}/pause` / `…/unpause` (C5 manual pause/unpause — reason `"manual"`, clobber-proof against C4 budget-cap reason), `GET /jobs/batches[/{id}]` (computed-on-read rollups; includes `paused_at`/`paused_reason` C4 fields + `archived`/`unarchived` Notion-archive counts), `GET /jobs/batches/{id}/jobs` (per-lesson-latest drill-in), `GET /jobs/batch/{id}/cost` (C4 observability: `batch_api_cost_usd`, `paused_at`/`paused_reason`, `fleet_api_paused_at`/`fleet_api_paused_reason`), `POST /jobs/batch/{id}/retry-archive` (0106 — backgrounded head-side re-push of `done`+un-archived lessons via idempotent `archive_job`; `_REARCHIVE_TASKS` single-process double-click guard + `_rearchive_sweep`; returns `{queued, already_running}`; **`?force=true` (0114)** sweeps ALL `done` lessons incl. already-archived via `done_job_ids` and clears+rewrites their stale leaf pages — the regen-wave refresh lever; run after the wave completes). `_rollup_payload` is the single batches serializer feeding all 3 paths; it gains keyword-only `archived`/`unarchived` defaulted args (0106).
- **`workers.py`** — `GET /workers` (fleet liveness: every registered worker + derived `online` flag); `POST /workers/{pc_id}/drain` / `…/undrain` (C5 `fleet-ctrl-4`: set worker `status="draining"` — worker self-drains on its next registry beat without clobbering the signal back to `"online"`).
- **`sa_keys.py`** — SA key distribution surface (worklog 0107): `GET /sa-keys` (key pool list, metadata only), `POST /sa-keys` (upload + validate via `sa_key_validate` + sha256 dedup), `DELETE /sa-keys/{id}` (409 if assigned), `GET /sa-keys/assignments` (all host→key assignments), `PUT /sa-keys/assignments/{hostname}` (assign), `DELETE /sa-keys/assignments/{hostname}` (unassign — non-destructive), `POST /sa-keys/assignments/{hostname}/scrub` (revoke), `GET /sa-keys/{id}/download` (**header-auth only** via `get_current_user_strict` — rejects `?token=`, 503s when `AUTH_TOKEN` is empty; serves raw bytes, never `private_key`).
- **`notion.py`** — `/notion/grades` + `/notion/grades/{id}/subjects`: browse the Notion lessons tree for the Fetch-From-Notion flow. **`GET /notion/grades/{grade_page_id}/available-languages`**: returns `{app_subject: {lang: {page_id, has_textbook}}}` — the per-language availability map used by the prepare-from-Notion language picker in the Fleet launcher.
- **`health.py`** — `/health`.
- **`settings.py`** — `GET /settings/launch-defaults` (returns the singleton's 11 fields, incl. `output_language` and the 3 new content fields) + `PUT /settings/launch-defaults` (validates non-null provider/model pairs + known manifest values + valid output_language, upserts the row; HTTP 422 on null provider/model — prevents a launch-bricking footgun). The only write surface for content/judge/extract model defaults and the global output-language default; credentials stay in `.env`.
- **`__init__.py`** — assembles `/api/v1` router. **Order matters:** `batch` registers before `jobs` so static `/jobs/batches*` isn't swallowed by dynamic `/jobs/{job_id}`.

## `app/services/` — the engine
- **`agent.py`** — **LLM surface & primary orchestrator.** `run_phase` / `run_phase_prompt` (markdown phases, with the per-phase JSON-`schema` mode + one retry), `extract_toc` (+ `_toc_source_pdf` front+back vision-window fallback for scanned TOCs, worklog 0072), **`validate_toc(book_id, entries, transport, provider, model)`** (worklog 0108 — post-extract vision validator: ONE Gemini-2.5-flash vision call compares the extracted TOC against the book's printed contents-page image via `_toc_source_pdf`; returns `{status: verified|mismatch|skipped, detail: str}`; **never raises** — any failure returns `status="skipped"`; prompt-build is inside try/finally so no partial state escapes), `summarize_lesson` (+ `correction_hint` param for a fidelity regen) + `read_whole_book_text` (whole-book-text extract), `summarize_lesson_vision` + `read_page_range_text` + `extract_text_is_too_sparse`/`pdf_page_count` (worklog 0070 extract fallbacks — vision page-window for scanned/sparse books, text subset for oversize), `extract_lesson_context` (legacy PDF-attach path, not called by the pipeline), `record_cached_lesson_extract`; **`validate_extract_summary` (Gate B, extract coverage-contract round-2)** is now a structural check, not a char-count: a refusal marker always fails; otherwise any output that parses into ≥1 recognized section via `content_lint.contract_has_items` passes regardless of length, falling back to the low `extract_min_summary_chars` floor (120) only when no contract section parses at all — the built-in extract prompts (`_SUMMARIZE_LESSON_PROMPT`/`_SUMMARIZE_VISION_PROMPT`, sharing `_CONTRACT_INSTRUCTIONS`) instruct the model to emit the fixed English headings `## Concepts & terms`/`## Rules & theorems`/`## Formulas`/`## Worked-example types`/`## Key facts` with items in the lesson's language; **extract-quality guards (worklog 0111):** `_alpha_plausibility_ratio` (expected-alphabet Latin∪Cyrillic∪Uzbek ratio, floor `extract_min_alpha_ratio`=0.70) wired into `validate_extract_text` (Gate A) + `_toc_text_is_usable` (TOC gate) → garbled/mojibake text routes to vision (the `/Gxx` glyph case already recovers via `_decode_glyph_text`; this catches cp1251 mojibake the letter-density gate passes); and the extract-fidelity trio `extract_math_expressions`/`extract_fidelity_candidates` (free — fraction/equation exprs absent from source, `/`-or-`=` AND digit-or-paren) → `verify_extract_fidelity` (gemini-flash, `ExtractFidelityVerdict`, **fail-open**) — the judge can't see extract drift (grades vs the extract, exempts worked-example arithmetic), so it's caught at extract time; `_resolve_model` / `_PROVIDER_DEFAULT_MODEL` (only `claude` + `opencode` carry a default); `_PLACEHOLDER_RULES` + `_VISUAL_PHASES` (visuals are described placeholders, never `<svg>`); concurrency semaphore + usage recording. `_spawn` is now a **retry-on-rate-limit wrapper** over `_spawn_once` (the single-attempt body that acquires the semaphore + reaps the process tree): on a transient 429 (`_is_rate_limited`) **or a transient connection/DNS error** (`_is_transient_net` — `getaddrinfo`/`HTTPSConnectionPool`/`WinError`/`connection aborted`/`timeout`, fleet-net-1 worklog 0089) it backs off (`_rate_limit_delay`, config `rate_limit_*`) and retries, otherwise returns unchanged (auth/`MAX_TOKENS`/session-limit stay terminal) — the reactive half of `concurrency-knob-1`. `_spawn_once` dispatches `transport=api` gemini/claude calls to `api_transport.generate` (early, before the binary lookup, still inside the semaphore); all other providers go through the CLI subprocess path. `_spawn_failure_message(provider, transport, rc, stderr, text)` builds the transport-aware failure string (says "api" on the SDK path, embeds the real error preview) recorded into `agent_usages.error_message` + `raw_envelope["error"]` on a failed `run_phase`/`summarize_lesson`.
- **`api_transport.py`** — **direct provider-SDK generation for `transport=api`** (gemini `google-genai`, claude `anthropic`); returns the same `(rc, text, usage, stderr)` 4-tuple as `_spawn`; dispatched from `_spawn`. Mirrors `_auth_env` credential logic; loud truncation (claude `stop_reason==max_tokens` / gemini `MAX_TOKENS`); per-provider cached-token semantics. **gemini accepts PDF/image attachments** (multimodal `Part`s over Vertex — scanned-book vision via api, `api-vision-1` worklog 0094); **claude stays text-only** (attachments → `NotImplementedError`).
- **`agent_models.py`** — `MODEL_MANIFEST`: the single source of truth for valid `(provider, model)` pairs; enforced on generate, served to the frontend. Also home to **`OUTPUT_LANGUAGES = {"uz", "en", "ru"}`**, **`validate_output_language(v)`**, and **`resolve_output_language(explicit, global_default)`** — the domain helpers for the medium-of-instruction axis (worklog 0099).
- **`pricing.py`** — verified per-token `PRICE_MAP` + `cost_usd(provider, model, usage)`; feeds the per-transport `$` rollup on `/agent/stats`. Per-provider cached-token semantics (gemini prompt-inclusive vs claude disjoint).
- **`pipeline.py`** — **per-job state machine.** Head: per-section `extract` (pinned cheap model, with Gate-A/Gate-B + failover; after Gate B on the local-text branch, `_verify_and_maybe_regen_extract` runs the extract-fidelity guard — free candidate scan → gemini-flash verify with a lesson-scoped source via `_verify_source_for_section` → regen once on confirmed drift, worklog 0111). The extract prompt-cache key is `"builtin:extract:v3"` (bumped from `v2` for the coverage-contract prompt change — invalidates cross-job extract-reuse so every active book re-extracts once, organically per-job). At job finalize, `_coverage_warnings_for_job(rows)` (pure) parses the extract row's contract via `content_lint.parse_extract_contract` / `lint_coverage` against the assembled non-extract packet markdown and, if any contract item's vocabulary is wholly absent, appends `lint:coverage_thin` finding(s) to the extract row's `validation_warnings` — warn-only, wrapped in try/except so it can never fail the job. Tail: DAG-parallel content phases (wave scheduler off `flows.PHASE_DEPS`). Each phase runs `_run_with_failover` and the `phase_judge` LLM judge, then stores `output_md` on its `phase_outputs` row. No assembly stage. `_run_with_failover` checks `failure_classifier.is_session_limit(exc)` **before** `classify` (worklog 0089): under the batch's resolved `session_limit_strategy` (`resolve_session_limit_strategy`), `switch` treats it as a `wall` (immediate failover off claude down `failover_provider_order`) while `pause` raises `SessionLimitPause` (propagated uncaught via `except SessionLimitPause: raise` guards before every broad catch). `pipeline.run` captures `job.output_language` once at start and threads it to every `get_prompt`/`get_prompt_hash` for content phases AND to all three `phase_judge.judge(output_language=...)` call sites — generator and judge always use the **same-language** prompt contract (worklog 0099).
- **`subjects.py`** — **single source of truth for supported subjects** (full Uzbek curriculum, grades 1–11). `SubjectDef`(code, label, family, game, language, Notion keywords, **`ru_keywords`/`en_keywords`**) + `REGISTRY`/`SUBJECT_CODES` + `notion_keyword_pairs(language="uz"|"ru"|"en")` (longest-first, language-aware; `uz` = existing Uzbek keyword list, `ru`/`en` = their respective keyword sets on `SubjectDef`) + `history_variant()` (derives the **Jahon / O'zbekiston** variant from a book filename — same apostrophe-fold as the Notion archive split; feeds the computed `BookOut.subject_variant` + batch payload, which the FE renders as "History · Jahon · grade N"). `flows`, `prompts`, `notion_fetch`, and the FE all derive from this. Add a subject here (+ mirror in `web/src/lib/types.ts`/`subjects.ts`).
- **`flows.py`** — `SUBJECTS` + `SUBJECT_GAME` (derived from `subjects.REGISTRY`; `SUBJECT_GAME` is now a recommendation-only hint, not consumed by the flow), `flow_for(subject)` (the **11-phase** sequence — generates all four interaction mini-games every job, the full Gamified Practices set), `PHASE_DEPS` (DAG deps) + `filter_prior_outputs`/`resolve_phase_deps`, **`order_phase_selection(subject, selected)`** (PR37 phase-picker: orders a user-chosen phase subset against the canonical flow; `pipeline.run` re-filters the stored subset against the live flow) + **`selection_missing_prompts(selected, custom_prompts)`** (PR39: a picked-phase subset must carry an uploaded prompt for every phase, else `/generate` and `/jobs/batch` reject with 400), per-phase output caps, SVG-stripping of prior outputs.
- **`prompts.py`** — prompt resolver: `get_prompt(subject, phase, provider_suffix="", output_language="uz")` reads `prompts/_general/<phase>.md`, substitutes `{{SUBJECT}}`, `{{LANGUAGE_RULES}}` (resolved by `_resolve_language_rule(subject, output_language)` against `MEDIUM_RULES` — three blocks for `uz`/`en`/`ru`; L2 language-class subjects (`subjects.language ∈ {english, russian}`) keep their L2 **target** (english/russian) but their scaffolding **bridge follows the medium** via `_l2_rule(target, bridge_medium)` — `l2-bridge-follows-medium`, worklog 0109; uz byte-identical to the legacy Uzbek-bridge block. Was the "L2 carve-out" [0099], now reversed for the bridge only; for **en/ru media** `_resolve_language_rule` appends `_LOCALIZE_HEADINGS_CLAUSE` so section headings/phase title/subject name localize too — worklog 0117, uz untouched), and `{{FAMILY_RULES}}` (CBP + flashcards, per subject-family). `SUBJECT_LABELS`/`_SUBJECT_FAMILY` derive from `subjects.REGISTRY`. `USE_SUBJECT_PROMPTS=False` ⇒ the per-subject dirs are dormant.
- **`phase_judge.py`** — the LLM judge: grades each phase against its own prompt contract (cite-then-refute), tags failures `major`/`minor`, severity-gates regeneration. Judge provider/model come from `job.judge_provider`/`job.judge_model` (stamped at launch from `launch_defaults`; seed default `claude-opus-4-7`). `_FIDELITY_RULE` instructs the judge to treat the `--- LESSON CONTEXT ---` block as the ground-truth source for fact-checking. `_fidelity_flags` is a conservative warning-only deterministic year-signal (cross-checks years in output vs source; skips math/exercise lines; never gates regen). PR37 adds a `contract_override` arg: the judge grades a custom-prompted phase against the **custom** prompt (`contract = contract_override or get_prompt(...)`) — fidelity fact-checking against LESSON CONTEXT stays in force either way. `judge(output_language=...)` param (worklog 0099): the judge resolves its own `get_prompt` against the same `output_language` as the generator, so it always grades against the correct-language contract. A content-policy **refusal** is classified distinctly (`_is_refusal` → `JudgeOutcome.refused`) so it isn't bucketed with transient `unavailable`; the pipeline records `judge_status="refused"`, skips the retry-once, and keeps the infra string out of `validation_warnings`.
- **`golden_eval.py`** — **R20 quality-regression harness** (CQ-E, worklog 0113; standalone/offline, read-only — not wired into the pipeline). `score_packet(entry, phases, source_text, next_lesson_title, *, provider, model, transport, llm=)` scores a packet across 6 audit dims → `PacketScore`. Deterministic dims (FREE): `score_language` (CQ-B `content_lint` + a stricter mixed-script + English-scaffolding blacklist, non-`en` lessons only), `score_reflection` (past-tense fabrication verbs, not the bare "Needs Retry" label), `score_error_detection_format`. LLM dims (paid, `agent.run_phase(schema=RubricVerdict, transport=api)`, degrade-to-`pass`): `score_boundary`/`score_answer_key`/`score_broken_question`/`score_extract_fidelity`; `answer_key` reads CQ-C `solver_status` via `getattr`. `diff_scores(..., gated_only=)` — the exit-code gate is authoritative only on `GATED_DIMENSIONS` (`language`,`reflection`; LLM dims advisory — audit-check measured them ~40%). Golden set + source fixtures + committed baselines live in `tests/golden/`. Runner/gate: `scripts/golden_eval.py` (`--job`/`--baseline`/`--emit-baseline` [E4-guarded]/`--audit-check`).
- **`content_lint.py`** — deterministic, **no-LLM** post-phase content lint (CQ-B, worklog 0110). `lint_phase(phase_name, output_md, *, subject, output_language)` returns advisory `LintFinding`s: mixed Latin+Cyrillic words, structural English-template tokens (`Mode:`, `Needs Retry`, `red herring`), and calques (`qizil seld`) on every non-extract phase; missing `source`/`inferred` misconception provenance tags on `flashcards`; and the error-detection **EXACTLY-ONE-broken-block** + Reveal-consistency FORMAT contract (R21.3). The broken-marker vocab (worklog 0117) recognizes `N-blok`/`N-yorliq` block nouns, the `(BU BLOK XATO)`/`(Broken)` marker forms, and `reveal`/`ochish`/`oshkor` reveal headers; a `ru_uzbek_leak` check flags leftover Uzbek template tokens (`Hali emas`, `Kuchli/Zaif tomonlar`) in `output_language=="ru"` output (regression guard for the round-2 localization fix). **Warn-only**: `pipeline._execute_phase` folds `findings_to_warnings(...)` (`lint:<code>` prefix) into the same `phase_outputs.validation_warnings` the judge uses — never gates a regen, never fails a job (pure functions, defensively wrapped). Semantic answer-key correctness is out of scope by design (that is CQ-C). **Extract coverage-contract (round-2):** `parse_extract_contract(md)` parses the extract's enumerated `## Concepts & terms`/`## Rules & theorems`/`## Formulas`/`## Worked-example types`/`## Key facts` headings into `{canonical_section: [items]}` (lenient on header level/case; unrecognized or empty sections drop out); `contract_has_items(md)` is the boolean used by `agent.validate_extract_summary` (Gate B) to accept a well-formed contract regardless of length; `lint_coverage(contract_md, packet_md)` is the warn-only post-job check — for each contract item (Formulas excluded, symbol-heavy) it checks whether the item's salient tokens appear anywhere in the assembled packet, emitting one aggregated `coverage_thin` finding for whatever's wholly absent (conservative — under-reports by design, a nudge not a gate), consumed by `pipeline._coverage_warnings_for_job`.
- **`model_tiers.py`** — judge model selection / self-fallback. The no-self guard uses a **generator-aware** `_self_fallback` (two distinct frontier peers, `_PRIMARY_SELF_FALLBACK=claude-opus-4-7` / `_ALT_SELF_FALLBACK=gemini-3.1-pro-preview`, returning whichever is NOT the generator) — provably non-self for any generator, not a single fixed constant that could itself self-match. `worker._compute_capabilities` reads `_self_fallback((judge_provider, judge_model))` for the `judge_fallback_api_ok` claim-gate flag. **`resolve_solver` is a thin alias of `resolve_judge`** (worklog 0112) — the solver has the identical never-self requirement.
- **`solver.py`** — the LLM **answer-key solver** (CQ-C, worklog 0112). `solve()` independently re-solves a phase's items and flags where the generated key is wrong; a near-clone of `phase_judge.judge` (one structured `agent.run_phase(schema=SolveVerdict, phase_name="__solver__", operation="solve:<phase>")` call; degrade-never-blocks except api-auth re-raise; imports `phase_judge._is_auth_error`/`_is_refusal`). Only `confidence=="high"` discrepancies set `has_mismatch` (→ regen) — low/medium are advisory, so it is **conservative (zero false positives)**. `pipeline._execute_phase` runs it AFTER the judge/regen block for `_SOLVER_PHASES = (memory-check, practice-error-detection, practice-rlc)`, regenerates once on a high-conf mismatch, and records `phase_outputs.solver_status`. **Recall boundary (characterized):** catches objective sign/arithmetic key errors, misses conceptual truth-value + expression-equivalence errors on gemini-3.1-pro — those → CQ-E's rubric. Per-role `solver_provider/model/transport` columns mirror the judge (launch_defaults/jobs/batches, mig 0043, seeded `gemini-3.1-pro-preview`); `jobs.claim_next_job`'s `solver_ok` clause gates api-solver jobs like `judge_ok`.
- **`failure_classifier.py`** — classifies a phase failure (transient / wall / model-not-found) to drive retry-vs-failover. Also `is_session_limit(text)` (keyed on a parseable `resets <clock-time>` clause — robust to the `_WALL` "usage limit" overlap) + `parse_session_limit_reset(text, *, now)` (→ next-occurrence UTC, injected clock, `settings.session_limit_default_tz`) for the Claude session-limit autopause (worklog 0089).
- **`errors.py`** — `SessionLimitPause(reset_at)` (import-free): raised by `_run_with_failover` under the `pause` strategy, caught by the worker.
- **`worker.py`** — Postgres-backed queue (`FOR UPDATE SKIP LOCKED`); per-job heartbeat + lease-reclaim; a **dedicated registry-heartbeat task** (`_drain_check_and_beat`, C5): beats the `workers` table every 30s even when all slots are busy — and on each beat checks `workers_repo.get_status(self.pc_id)`; when `"draining"`, calls `stop()` and skips the `upsert_heartbeat("online")` write that would clobber the drain signal; on a normal beat it also **publishes the worker's `CAPABILITY_BLOB`** (`_capability_blob(env)` → `{cli:{5 providers}, api:{claude,gemini}}`, computed once at module load; `_api_capable(env)` is shared with `_compute_capabilities` so the published view and the claim-gate `CAPABILITIES` can't drift) into `workers.capabilities` for the launcher fleet-serveability view; stale-`cancelling` sweep; embedded in the API or run standalone per fleet PC (`python -m app.services.worker`). `_compute_capabilities` is now **credential-only** (`{can_claude_api, can_gemini_api}`) — no settings default lookup (claim gate v3, 0097): launch endpoints stamp concrete `judge_provider`/`extract_provider` onto every job row, so the gate reads job columns directly against the worker's credential flags. **`_budget_monitor`** (C4): a background loop (period: `COST_CHECK_INTERVAL_SECONDS`, default 60s) reading the cost ledger and gating api-spending jobs by pausing batches (`batches_repo.pause_batch` → `batches.paused_at`/`paused_reason`) or the fleet (`budget_repo.set_api_paused` → `budget_state.api_paused_at`) when spend exceeds `COST_CAP_BATCH_USD` / `COST_CAP_FLEET_DAILY_USD`.
