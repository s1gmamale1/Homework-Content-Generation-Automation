# Plan — Retry book TOC extraction (re-prepare a failed/stuck book)

Branch `feat/toc-retry` (off `origin/Nggaev-v2` @ `14fd30e`). The motivating case: `a0173601` failed TOC extraction (claude weekly-limit) and there was **no way to re-trigger it** — it needed a hand-run script. This adds a first-class retry, mirroring the existing job-retry.

## Approach & key decisions

**Problem.** TOC extraction (book "preparation") fires once, as a fire-and-forget `asyncio.create_task(toc_extractor.run(...))` on upload / from-notion (`books.py:96`). If it fails (rate-limit, transient provider error, a crash mid-run leaving a stuck `toc_extracting`), there is **no retry path** — only delete + re-upload. Generation/**job** retry already exists (`POST /jobs/{id}/retry` + FE `retryJob`); the gap is the book-prep step.

**Chosen approach — mirror job-retry for books.** A `POST /books/{book_id}/toc/retry` endpoint that re-fires the same background extraction, plus a FE **Retry** button on failed/stuck books (mirroring the existing `retryJob` button). Refactor the duplicated trigger block (upload + from-notion both do the `create_task`/`_TOC_TASKS` dance) into a shared `_start_toc_extraction(book_id, pdf_path, subject)` helper and reuse it in all three call sites — DRY, and the retry path is then identical to the upload path.

**Key decisions (locked with the user + verified against code):**
1. **Retryable states: `failed` + `toc_extracting` only** (user-chosen). `failed` = the rate-limit/transient case; `toc_extracting` = a hung/crashed extraction (the `lifespan` orphan-sweep marks *stale* ones failed, but a freshly-stuck one needs a manual kick). `toc_ready` (has lessons) and `uploading` (mid-upload) are **blocked** with 409 — a ready book is redone via delete+re-upload, not a silent clobber.
2. **Re-uses the exact upload trigger** — `_start_toc_extraction` holds the `create_task` + `_TOC_TASKS.add` + `add_done_callback(discard)` (verified `books.py:96-98`). `toc_extractor.run` itself sets `toc_extracting` → `toc_ready`/`failed` and publishes SSE on `book:{id}`, so the FE's existing `GET /{id}/toc/stream` shows live progress on retry with no new plumbing.
3. **Optimistic status flip** — the endpoint sets the book to `toc_extracting` synchronously (via `books_repo.set_status`) **before** returning, mirroring job-retry's synchronous `reset_for_retry`, so the UI immediately reflects "re-preparing" without waiting for the task to commit.
4. **Guards:** 404 if book missing; 409 if status not retryable; 409 if the source PDF is missing on disk (`storage.book_pdf_path(id)` doesn't exist → "re-upload the book", since extraction reads it). `subject` comes from `book.subject` (stored).
5. **Concurrency:** the in-process `_TOC_TASKS` set is best-effort; a retry of a *genuinely* still-running extraction could double-fire (rare — the user opted into `toc_extracting` retry for the stuck case). The second run just re-sets status and overwrites; `toc_repo` upsert/replace on persist means no duplicate entries (verify `bulk_create` behavior in Task 1 — if it appends, clear existing entries for the book before persist). **Load-bearing check for Task 1.**
6. **Auth:** mutating endpoint → `user: dict = Depends(get_current_user)` like `upload_book` (not the bare `get_book`).

```python
def _start_toc_extraction(book_id: UUID, pdf_path: Path, subject: str) -> None:
    """Fire-and-forget the background TOC extraction, keeping a strong task ref."""
    task = asyncio.create_task(toc_extractor.run(book_id, pdf_path, subject))
    _TOC_TASKS.add(task)
    task.add_done_callback(_TOC_TASKS.discard)
```

**1b. The endpoint:**
```python
@router.post("/{book_id}/toc/retry")
async def retry_toc_extraction(
    book_id: UUID,
    session: AsyncSession = Depends(get_session),
    user: dict = Depends(get_current_user),
) -> BookOut:
    """Re-run TOC extraction for a book stuck in `failed` or `toc_extracting`.
    Mirrors POST /jobs/{id}/retry for the book-preparation step."""
    book = await books_repo.get(session, book_id)
    if book is None:
        raise HTTPException(404, "book not found")
    if book.status not in ("failed", "toc_extracting"):
        raise HTTPException(
            409,
            f"cannot retry TOC extraction from status '{book.status}' "
            "(only `failed` or a stuck `toc_extracting`)",
        )
    pdf_path = storage.book_pdf_path(book_id)
    if not pdf_path.exists():
        raise HTTPException(409, "source PDF missing on disk — re-upload the book")
    await books_repo.set_status(session, book_id, "toc_extracting", error_message=None)
    await session.commit()
    _start_toc_extraction(book_id, pdf_path, book.subject)
    return await _book_out_with_toc(session, book_id)
```
